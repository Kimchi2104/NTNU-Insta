## 貼給 Claude（整段複製）

```text
【卡 02 合併審稿】
集號：　　　（可以列 2–4 集；留空＝找 04_腳本庫/_審稿/ 有交件、04_腳本庫/ 還是 v0 的集數，發布日最近的先）

這個對話只做一件事：把外部審稿合併進上面那幾集，升成 v1。先讀：
1. 02_製作流程SOP/開工指令/README.md 第三節「共同規則」
2. 02_製作流程SOP/外包任務書/README.md（交件規則、交件紀錄）
3. 04_腳本庫/_審稿/審稿整合紀錄_第2批.md（紀錄格式，以及「審稿本身的錯」那一節——就是照這樣做）
4. 該集 v0，和 _審稿/{集}_*.md 全部

方法：
- 每一條意見都自己驗證過才採用：對回原典、07_資料來源 的 CSV、重算（ephem）。審稿常見的錯：描述稿子裡不存在的句子、互相抄、憑印象補頁碼、把推測寫成「已比對原典」——這類直接判「不採用」並記下來
- **中文版不設全片秒數上限**（2026-11-10 起）：審稿裡「全片超時」「刪到 180 秒」「為了時長刪某鏡」的意見一律不採用，整合紀錄記一行「不採用：中文版不為時長刪內容」就好，不用逐條驗證。只有離題、重複、事實站不住才刪。v0 表頭與 ⚠ 清單裡的「壓縮建議」「節目表原訂 N 秒」升 v1 時拿掉，表頭只留實際秒數
- 採用的改進稿；🔴 沒採用的要寫原因。每格字/秒重算，仍 ≤ 4.5；統一開頭不動；分鏡表的鏡號不重排（刪的鏡寫進「刪減紀錄」）
- v0 → v1：git mv 後改內容（v0 不留）。已是 v1 再審：新開 v2，v1 留著
- 寫 04_腳本庫/_審稿/審稿整合紀錄_第{N}批.md：每集採用／不採用／有疑義（附我選的保守處理）三張表＋「審稿本身的錯」；新學到的教訓用一兩句加進 外包任務書 01／02 的硬規定
- 更新 外包任務書/README.md 的交件紀錄表；節目表「狀態」欄改「逐字稿 v1（已查核＋外部審稿 {日期}）；素材、Canva 未做」
- 交件裡若有指出資料 CSV 的錯，改 CSV（保留原檔的 BOM 與換行）

結束：commit、PR、合併。回報照共同規則；有疑義的條目照保守預設處理（維持中文原文或加限定語，不刪），在回報裡列出理由，不要等確認。
```
