# 外包任務書（給 Gemini／Antigravity 等外部代理）

這個資料夾的每一份 `.md` 都是**可以整份貼給外部代理的完整指令**。代理只需要能讀這個 NTNU Insta 資料夾（或你貼給它的檔案內容）與上網。

## 工作流程

```
Claude 寫逐字稿 v0（04_腳本庫/*-逐字稿-v0.md）
   │
   ├─▶ 01_網路考據.md   （Gemini：把每集「⚠ 待查核清單」逐條查到出處）
   ├─▶ 02_審稿Critic.md （Antigravity：四個角色各自審一輪）
   │
   ▼  交件到 04_腳本庫/_審稿/
Claude 合併考據與審稿意見 → 逐字稿 v1（已查核）→ 星圖素材 → Canva
   │
   └─▶ 03_英文版改寫.md （英文稿 v0 的規格；由 Claude 寫，見 ../開工指令/05_英文稿v0.md）
         └─▶ 04_英文審稿.md （Gemini 審英文稿 v0 → Claude 合併成 v1，../開工指令/06_合併英文審稿.md）
```

每一段 Claude 要做的事都有一張「開工卡」：`../開工指令/README.md`。

## 一句話指令（Antigravity）

不用每次貼整份任務書。repo 根目錄的 `AGENTS.md` 寫了句型與交件六步，在 Antigravity 開新對話只說：

- 「做 A-22 考據」
- 「做 A-22，角色 1」（1＝天文、2＝文化、3＝敘事、4＝語言；一個角色一個對話，一個對話最多三集）
- 「缺什麼」（它會跑 `進度.py --missing` 把缺件清單貼回來）

要貼哪幾句，看 `06_發布月曆/進度板.md`「送審缺件」，每一行就是一句。它沒照做時，句子前面加「照 AGENTS.md，」。每個對話最後一則訊息第一行必須是「已交件：…（commit …，已 push）」或「未交件：…」；沒看到這行就當作沒交。

## 交件規則（一定要照，Claude 才能自動合併）

- 一律寫到 `04_腳本庫/_審稿/`，檔名：`{編號}_{任務}_{代理名}.md`
  例：`A-16_考據_gemini.md`、`A-16_審稿-天文_antigravity.md`、`A-16_審稿-文化_antigravity.md`
- **不要直接改逐字稿本身**。意見寫在交件檔裡，由 Claude 合併，才能保留修改紀錄。
- 每條意見都要有：位置（鏡號或段落）、原文、問題、建議改法、出處（網址或書目＋頁碼）。沒有出處的意見請標「（推論）」。
- **整份丟，不用改字**：每份任務書都寫成可以直接連同逐字稿丟給代理的樣子；`{編號}`、`EN??` 代理自己從檔名帶入。
- Antigravity 交件後會自己 push 到 main，不用另外交代（不是在 Antigravity 做的才要你推，見下一節）；然後開對應的開工卡對話（`../開工指令/02_合併審稿.md` 或 `06_合併英文審稿.md`）。

## 自動送審（Antigravity `/schedule`，用 Credit、不吃 Claude Usage）

在 Antigravity 開一個對話，用 `/schedule` 設每天一次（例如 09:00），貼：

```
【自動送審】每天一次，一次只做一集。
1. 終端機：git checkout main && git pull --ff-only origin main
2. 讀 06_發布月曆/進度板.md「現在先做」裡的「送審」那一行，取第一個集號（例 A-22）。沒有就跳到第 5 步。
3. 照 02_製作流程SOP/外包任務書/01_網路考據.md 做那一集的考據，寫到 04_腳本庫/_審稿/{集號}_考據_gemini.md。
4. 照 02_審稿Critic.md 做四個角色，各寫一個檔；每個角色從頭讀逐字稿、不要看自己前一個角色寫的東西。
5. 進度板「英文」那一行若有「Ⓑ 送 Gemini」，照 04_英文審稿.md 審那一集（附中文定稿）。
6. 終端機：python3 02_製作流程SOP/進度.py && git add 04_腳本庫/_審稿/ 06_發布月曆/進度板.md && git commit -m "{集號} 交件（自動送審）" && git push origin main
7. 最後回報：做了哪一集、哪些檔。
```

四個角色由同一個代理依序做，獨立性比開四個 agent 差一點；想保留完全獨立就只排第 3 步，四角色自己手動開四個對話。對話第一行寫「【A-22 考據】」這類標題，側欄才看得出來。

## 交件後的同步

**Antigravity 交件後會自己 push，不用另外交代。** Claude 從 repo 讀。它只該加 `04_腳本庫/_審稿/`；它自己產生的工作檔（`.agents/`、曆表）已在 `.gitignore`。

**但它的工作目錄必須停在 `main` 分支。** 11/10 發現它一直推到 `browser_teamwork_preview_boost`（以前 `/teamwork-preview` 留下的分支），A-22～A-24 的交件在那裡躺了一天，main 上的 Claude 與進度板都看不到。檢查與修正，在 Antigravity 終端機跑一次：

```bash
git branch --show-current          # 要是 main
git checkout main && git pull --ff-only origin main
```

GitHub Desktop 的「Current Branch」也要是 main。推到別的分支的交件，要開 PR 併進 main 才算交件。

如果 Antigravity 回說「這是 secondary worktree，main 已在主工作目錄被 checkout」，表示它開的是 `/teamwork-preview` 留下的副工作目錄，不是主資料夾。修法：在 Antigravity 用 Open Folder 改開主資料夾 `NTNU Insta`（分支就是 main），然後叫它跑：

```bash
git worktree list                                   # 看副工作目錄的路徑
git worktree remove --force <副工作目錄路徑>
git branch -D browser_teamwork_preview_boost
git push origin --delete browser_teamwork_preview_boost
```

只有**不是在 Antigravity 裡做**的交件（例如 Gemini 網頁版的深度研究）才要你自己推：GitHub Desktop 先 Fetch→Pull，再勾選**只有** `04_腳本庫/_審稿/` 裡的新檔 Commit→Push。不要用「全部勾選」：11/08 就是這樣把 Antigravity 的 `.agents/` 工作檔、測試文件、16 MB 的曆表、以及它重建出來的舊版逐字稿一起推上去了。

推不上去時，跟 Claude 說「交件在 Drive，還沒 Push」，Claude 會用 Google Drive 連接器讀。
