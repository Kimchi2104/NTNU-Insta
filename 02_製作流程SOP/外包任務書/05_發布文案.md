## 每一集的步驟

1. `git branch --show-current` 要是 `main`；`git pull --ff-only origin main`。
2. 先讀三篇示範，照它們的樣子寫：`中文IG/A-22.md`、`聯盟FB/A-22.md`、`英文IG/EN16.md`。
3. 讀來源：
   - 中文集：`04_腳本庫/{集號}-*-逐字稿-v*.md` 版號最大的那一份（旁白、Caption 建議、首留言、聯盟版文案、考據備忘、星名表），和 `06_發布月曆/節目表_萬國星空_全年.csv` 那一列的發布日。
   - 英文集：`04_腳本庫/_英文版/EN{nn}-*-v*.md` 版號最大的那一份（Caption、Beats、Glossary）、對應的中文定稿、`06_發布月曆/英文譯名表.csv`，和 `06_發布月曆/節目表_萬國星空_英文版.csv` 那一列的發布日。
4. 打開初稿，照下面的規格改寫 `## 文案`、`## 首留言`、`## 備註` 三段。
5. 把第二行改成 `> 狀態：已潤稿（antigravity，2026-12-01）`（寫你的名字和當天日期）。其他以 `> ` 開頭的行不要動。
6. `python3 02_製作流程SOP/gen_caption_docx.py --check A-23`。有 ✗ 就改到沒有；△ 是提醒，看過就好。
7. 交件（見「交件」一節）。一集交完再做下一集。

## 規格：三種都一樣的

- **事實只能來自那一集的稿子。** 不上網查，不加稿子裡沒有的故事、數字、年代、引文。稿子裡的限定語（「有人認為」「一說」「推測」「據說」）要留著。
- **不寫怎麼算的。** 不出現 PyEphem、Python、「自算」「重算」「我們算了一下」、行星亮度用哪篇論文。數字和時刻照寫，直接講結果：
  - 原句：「我們用 PyEphem 算了一下：今天在開羅，要等到 8 月 5 日前後」→ 寫成「今天在開羅，要等到 8 月 5 日前後」。
  - 「（台北）」「以新竹尖石為準」這種講地點的話要留著。
- **資料來源要留。** 文獻、書名、作者、Stellarium 星空文化名稱與作者、星表（Hipparcos）、流星雨年曆這些都是；軟體不是。
- **純文字。** 不用 Markdown（不要 `>`、`**`、`` ` ``、行首的 `-`）。清單用「・」開頭。段落之間空一行。
- **內部用語不出現**：逐字稿、鏡頭幾、圖層、Canva、v1／v2、素材檔名、待查核、⚠。
- **原文星名照抄。** 西里爾字母、阿拉伯文、假名、帶附加符號的拉丁字母，從稿子複製，不要自己轉寫、不要改拼法。
- **時間的字要對發布日。** 「今天」「今晚」「明天」「下週五」「This week」都以節目表那一列的發布日為準；下一集預告寫節目表上排在後面的那一集（英文版照發布日排，不照 EN 編號）。初稿裡的日期、時刻、仰角是算好的，**數字不要改**；覺得不對就照樣留著，在 `## 備註` 寫「待確認：…」。
- `## 備註` 是給發文的人看的，不會貼出去。初稿裡已有的提醒（例如「改天發要換數字」）要留著。

## 規格：中文 IG

照這個順序：

1. **鉤子** 1–2 行。第一行要能單獨看懂（IG 只先顯示第一行）。
2. **知識點** 3–5 小段。每段一個小標（一個 emoji＋幾個字），一段只講一件事，寫出原文星名和中文意思。初稿裡「📚 …」的段落就是材料：挑最好懂的併進來改寫成順的句子，太細的考據留在首留言。
3. **這幾天抬頭看**（稿子裡有才寫）。
4. 「📌 圖卡…可以存起來」（初稿有才留）。
5. **下一集預告**一行。
6. **資料來源**一行，以「資料來源：」開頭；有首留言就加一句「完整考據在第一則留言。」
7. **hashtag** 8–10 個，一定有 `#萬國星空 #師大天文社`。

- 文案寫到 800–1,800 字；不要超過 2,000。
- `## 首留言`：放完整考據（初稿的「📚」段落，照原樣，一段一行）。沒有就寫「無」。
- 已經發過的集數（發布日在今天以前）：`## 備註` 寫「這一集已經發過，這份可以拿來編輯原貼文的文案」。七夕、A-01–A-04、A-06 的初稿有「📌 更正」段，要留著。

## 規格：聯盟 FB

- **第一句講天空，不講社團。**（「這幾天天一黑，獵戶腰帶就掛在南方高空」是對的；「師大天文社這集要介紹」是錯的。）
- 中間是知識點，一到兩段。
- 「這幾天晚上抬頭看得到嗎（台北）」那一段：數字照初稿，可以拆成「・」清單，不要改數字。
- 「資料來源：…」一行。
- 最後一行預告聯盟的下一篇：「下一篇（M/D 週X）：…」。下一篇＝節目表上發布日排在後面的那一集（聯盟跟 IG 同一天發）。
- hashtag 只有 `#萬國星空 #師大天文社`。
- 沒有首留言，`## 首留言` 寫「無」。
- 不要 IG 用語：「留言＋1」「連結在個人檔案」「收藏起來」、tag 別的帳號。
- 檔頭有 `> 發文：…` 的是舊片補貼（11 篇）：「（本片原發布於師大天文社粉專；…）」和「📌 更正」要留著，日期不要動。

## 規格：英文 IG

- 全部英文。星名原文（例如漢字 參）可以留。
- 事實只能比中文定稿少，不能多；英文稿 Glossary 和 `英文譯名表.csv` 怎麼拼就怎麼拼；限定語留著（"Some think…", "one story says…"）。
- 觀星的話用北半球通用的說法，不寫台北的時刻。
- 順序：鉤子（英文節目表「英文鉤子」那一句）→ 3–5 小段（emoji＋小標）→ This week（稿子有才寫）→ "Next Wednesday: …"（照發布日的下一集；隔的不是一週就寫星期幾或日期）→ "Sources are in the first comment." → hashtag 6–10 個，一定有 `#WorldSkyCultures`。
- 文案 900–1,500 字元。
- `## 首留言`：一行，以 `Sources:` 開頭，照初稿的出處，不加軟體名。

## 出文案檔

Kim 說「出文案檔」時才做。**一次只在一個對話做**（docx 是二進位檔，兩邊同時改會衝突）。

```bash
git pull --ff-only origin main
python3 -c "import docx" || python3 -m pip install --user python-docx
python3 02_製作流程SOP/gen_caption_docx.py
git add 06_發布月曆/文案/萬國星空_中文IG文案.docx 06_發布月曆/文案/萬國星空_FB聯盟文案.docx 06_發布月曆/文案/萬國星空_英文IG文案.docx

```

三個 docx 沒有變（`git status` 沒有東西可以 commit）就回「Word 檔已經是最新的」。回報時貼腳本最後三行（每份有幾集、其中初稿幾集）。

## 不要做的事

- 不確定的數字不要猜、不要自己重算；照初稿留著，在 `## 備註` 寫「待確認：…」。
